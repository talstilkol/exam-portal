📡 fetch שולח HTTP

Async + Promises + JSON

const res = await fetch('/api/users', {

  body: JSON.stringify(user)
});

🚂 Express מקבל

Routes + Middleware
השרת מנתב את הבקשה לפי URL. Middleware בודק token, validates body.
app.post('/api/users',
  authMiddleware,
  async (req, res) => {
    const data = req.body;
});
→ למד Express 5

4 השכבות של כל אפליקציית ווב:

  • 1.
  • צד לקוח (Frontend) — מה שהמשתמש רואה ולוחץ.
  • React בונה את הממשק מקומפוננטות.
  • Vite מקמפל את הקוד.

  • 3.
  • צד שרת (Backend) — "המוח" של המערכת.

  • Express מנהל Routes ו-Middleware.

  • 4.
  • בסיס נתונים — אחסון המידע.

🔄 המסע של בקשת ה-HTTP: מהדפדפן לשרת ובחזרה

כל לחיצת כפתור באפליקציה עוברת את 5 השלבים האלה (לחץ על כל שלב להרחבה):

1️⃣
דפדפן יוצר בקשה
Method + Path + Headers
הדפדפן מרכיב חבילה הכוללת את סוג הפעולה (GET/POST), כתובת היעד בשרת, ומידע מזהה (למשל טוקן אבטחה ב-Headers).
↓
2️⃣
fetch + Async/Await
שליחה אסינכרונית, בלי לחסום הדף
הפקודה fetch() שולחת את הבקשה. ה-await אומר לקוד להמתין בסבלנות לתשובה, בזמן שהמשתמש יכול להמשיך לגלוש כרגיל בלי שהדף ייתקע.
↓
3️⃣
JSON Serialization
המרת אובייקט JS → טקסט לרשת
רשת האינטרנט לא מבינה "אובייקטים" של JavaScript. היא מעבירה רק טקסט חלול. לכן, משתמשים ב-JSON.stringify() כדי לארוז את הנתונים למחרוזת טקסט אחידה לפני השילוח.
↓
4️⃣
שרת מעבד ומחזיר Status Code
2xx ✅ הצלחה 4xx ❌ שגיאת לקוח 5xx ⚠️ שגיאת שרת
השרת מחזיר קוד מספרי: 200 (הכל תקין), 201 (נוצר מידע), 400 (בקשה שגויה), 401 (אין הרשאות), 404 (נתיב לא קיים), 500 (השרת קרס באמצע העבודה).
↓
5️⃣
חזרה ללקוח: Parsing
response.json() → המרה חזרה לאובייקט JS

התשובה שחזרה מהשרת היא טקסט. כדי לחלץ את המידע ולהשתמש בו ב-React, מפעילים await response.json() הממיר אותו בחזרה לאובייקט JavaScript.

⚠️ fetch לא זורק Error על 404! חובה לבדוק res.ok 💡 חובה לרשום await לפני פעולת הפענוח.

3️⃣ תשתית Frontend ו-Routing
הקמת Routing בסיסי (BrowserRouter, Routes) ודפי UI הנדרשים (Login, List, Add, Edit).
4️⃣ Controlled Forms ו-Fetch
חיבור טפסים ל-State, שימוש ברכיב משותף ל-Add/Edit, וביצוע קריאות fetch לשרת.
5️⃣ ולידציות וליטושים
ולידציות כפולות (צד לקוח + צד שרת), טיפול Loading/Error, הוספת Search ו-Toggle.
🛡️ ולידציה כפולה = הציון שלך

🚫 ממה להימנע (Anti-Patterns)

❌ עיצוב לפני לוגיקה — אל תבזבזו זמן על CSS לפני ש-State עובד ונתונים מהשרת.

❌ שכפול קומפוננטות — השתמשו ברכיב Shared Form ל-Add ו-Edit.

🖼️ Primitive לעומת Object — מתי נשבר ומתי לא

  • אבל אם תיתני לה את הכתובת של הבית שלך, ושתיכן תיכנסו לאותו בית — אם היא תזיז ספה, גם את תראי.
  • זה by reference.

🟢 רמת סבתא

תחשבי על מספר טלפון לעומת כתובת של בית.

  • אם אני אומר לך "הטלפון שלי הוא 054-1234567" ואת רושמת אותו — יש לך העתק.
  • אם את משנה את המספר אצלך, שלי לא משתנה.
  • זה Primitive (מספר, טקסט, בוליאני).
  • אבל אם אני נותן לך את כתובת הבית שלי ואת באה ומשנה את צבע הדלת — גם אני רואה את השינוי, כי שנינו מסתכלים על אותו בית.
  • זה Reference (אובייקט, מערך, פונקציה).

💡 הכלל: פרימיטיבים = עותק עצמאי. אובייקטים = שניהם מצביעים על אותו דבר.

🟡 רמת ביניים

ב-JS יש שני סוגי זיכרון:

  • Stack — מהיר, קטן. שם נשמרים number, string, boolean, null, undefined. כל משתנה מקבל העתק עצמאי.
  • Heap — גדול, איטי יותר. שם נשמרים Object, Array, Function. המשתנה ב-Stack שומר רק כתובת (reference) ל-Heap.

    18. אבטחה מתקדמת: Access Tokens vs Refresh Tokens

    ניהול נכון של זהות משתמש מול שרת מבוזר, התמודדות עם פקיעת תוקף מבלי להוציא את המשתמש מהמערכת.

    18.1 למה צריך שני טוקנים?

    Access TokenRefresh Token
    טוקן גישה זמני (למשל 15 דקות). נשלח בכל בקשה.טוקן ארוך טווח (למשל 30 יום). נשמר בצד ובטוח.
    מכיל מידע על המשתמש (הרשאות).לא מכיל מידע, רק מחרוזת מזהה קריפטוגרפית מול ה-DB.

    19. מסד נתונים מתקדם: MongoDB Aggregation Pipeline

    עיבוד, סינון וקיבוץ נתונים מורכבים ישירות במסד הנתונים כדי לחסוך משאבי שרת.

    19.1 מה זה Aggregation?

    💡 מידע מורחב: במקום למשוך את כל הנתונים...
    במקום למשוך את כל הנתונים ל-Node.js ולעשות עליהם `reduce` ו-`filter`, אנחנו נותנים ל-Mongo לעשות את העבודה הכבדה בפס ייצור (Pipeline).
    שלב (Stage)תפקיד
    $matchמסנן את המסמכים (כמו filter). לדוגמה: רק לקוחות פעילים.
    $groupמקבץ את המסמכים ומחשב נתונים (כמו reduce). לדוגמה: סכום רכישות לכל משתמש.
    $projectבוחר אילו שדות להחזיר (כמו map).
    $sortמסדר את התוצאות הסופיות.
    db.orders.aggregate([ { $match: { status: "completed" } }, { $group: { _id: "$userId", totalSpent: { $sum: "$amount" } } }, { $sort: { totalSpent: -1 } } ])
    1. $match: מביא רק הזמנות שהושלמו.
    2. $group: מקבץ לפי מזהה משתמש, ומחבר את כל הסכומים.
    3. $sort: מסדר מהבזבזן הכי גדול לקטן.
