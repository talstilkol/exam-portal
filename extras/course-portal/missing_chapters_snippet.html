23. מסדי נתונים רלציוניים (SQL & PostgreSQL)

בניגוד ל-MongoDB (NoSQL), מסדי נתונים כמו PostgreSQL מסדרים את המידע בטבלאות קשיחות עם קשרים הדוקים (Relations) ביניהן.

23.1 טבלאות לעומת אוספים

מושגNoSQL (MongoDB)SQL (PostgreSQL)
שמירת נתוניםCollections (אוספים) של מסמכי JSONTables (טבלאות) עם שורות ועמודות
סכמה (Schema)גמיש, אפשר לדחוף כל שדה בכל רגענוקשה, חייבים להגדיר עמודות מראש
קשרים (Relations)לא טבעי, דורש פעולת populate (קצת איטי)טבעי ומהיר מאוד בעזרת פקודת JOIN
-- שליפת נתונים רלציוניים בשפת SQL SELECT users.name, orders.total FROM users JOIN orders ON users.id = orders.user_id WHERE users.country = 'Israel';
  1. SELECT: בוחר אילו שדות אנו רוצים לקבל.
  2. JOIN: מחבר את טבלת הלקוחות לטבלת ההזמנות לפי מזהה זהה. זה ה"קסם" של SQL.

24. Nest.js - ארכיטקטורה ברמת Enterprise

Nest.js הוא פריימוורק מעל Express, שכופה סדר וארכיטקטורה ברורה מאוד (דומה ל-Angular) בעזרת Decorators ו-Dependency Injection.

24.1 מושגי הליבה של Nest.js

  • Controllers: אחראים אך ורק על קבלת הבקשה מהלקוח (HTTP Routes) והחזרת תשובה. לא כותבים כאן לוגיקה עסקית!
  • Providers (Services): כאן יושבת ה"לוגיקה העסקית" העיקרית של האפליקציה (שליפה מהדאטאבייס, חישובים).
  • Modules: אוסף של קונטרולרים וסרביסים הקשורים לאותו נושא (למשל UsersModule).
// users.controller.ts import { Controller, Get } from '@nestjs/common'; import { UsersService } from './users.service'; @Controller('users') export class UsersController { // Dependency Injection - נסט מזריק את הסרביס אוטומטית! constructor(private readonly usersService: UsersService) {} @Get() // מאזין לבקשות GET /users findAll() { return this.usersService.getAllUsers(); // קורא ללוגיקה מהסרביס } }
  1. @Controller: דקורטור שאומר לנסט שזוהי מחלקה שמטפלת בראוטים.
  2. Dependency Injection: במקום לעשות `new UsersService()`, אנחנו מבקשים את זה ב-constructor ונסט מביא לנו עותק מוכן.

25. AI Engineering (פיתוח עם וסביב בינה מלאכותית)

כיום מצופה ממפתח פול-סטאק לדעת גם להשתמש בכלי AI כדי לתכנת מהר יותר (Cursor, Copilot), וגם לדעת לשלב מודלים בתוך האפליקציה (Vercel AI SDK, OpenAI).

25.1 מושגי מפתח בעולם ה-AI

  • Prompt Engineering: היכולת לנסח בקשה בצורה מדויקת כדי לקבל קוד תקין, לרוב כוללת מתן הקשר, דוגמאות וחוקים.
  • RAG (Retrieval-Augmented Generation): שיטה לתת ל-AI מידע מהדאטאבייס העסקי שלך (שלא אומן עליו) כדי שיענה תשובות רלוונטיות לעסק שלך.
  • Hallucinations: כאשר ה-AI "ממציא" תשובה בביטחון מלא. תמיד חייבים לוודא קוד שנוצר.

27. כלי פיתוח, Git וזרימת עבודה

איך עובדים בצוות בלי לדרוס קוד אחד של השני.

27.1 תהליך העבודה הסטנדרטי (Git Workflow)

  • Branching: לעולם לא כותבים קוד על ענף ה-main. פותחים ענף נפרד לכל פיצ'ר (לדוגמה: feature/login-page).
  • Pull Request (PR): אחרי שמסיימים, מבקשים למזג את הקוד חזרה ל-main. מפתח אחר בצוות אמור לאשר זאת (Code Review).
  • Merge Conflicts: קורה כששני מפתחים שינו בדיוק את אותה שורה בקובץ. הפתרון: לקרוא בעיון ולבחור אילו שינויים לשמור (Accept Current, Accept Incoming או לשלב את שניהם).
