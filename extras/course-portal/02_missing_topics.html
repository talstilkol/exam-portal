1️⃣ Classes ו-Inheritance

Class זו תבנית שאומרת איך לבנות אובייקט. כמו שעושים תבנית עוגה — אפשר להכין הרבה עוגות מאותה תבנית. כל אובייקט שנוצר מהClass הוא instance.

Class הוא syntactic sugar מעל prototype-based inheritance של JS. הוא מספק תחביר נקי לבניית אובייקטים מורכבים, ירושה (extends), ו-encapsulation עם methods פרטיים (#field).

Class בסיסי

💻 הצג קוד דוגמה
class BankAccount { // Constructor — רץ כשיוצרים אובייקט חדש constructor(owner, balance) { this.owner = owner; this.balance = balance; } // Method — פונקציה של ה-class deposit(amount) { this.balance += amount; return this.balance; } withdraw(amount) { if (amount > this.balance) { throw new Error('אין מספיק יתרה'); } this.balance -= amount; return this.balance; } getBalance() { return this.balance; } } // יצירת instance const account = new BankAccount('תל', 1000); account.deposit(500); // 1500 account.withdraw(200); // 1300 account.getBalance(); // 1300

Inheritance (ירושה) עם extends

💻 הצג קוד דוגמה
// Class הורה class Animal { constructor(name) { this.name = name; } speak() { return `${this.name} עושה רעש`; } } // Class ילד יורש מ-Animal class Dog extends Animal { constructor(name, breed) { super(name); // קורא ל-constructor של ההורה this.breed = breed; } // Override — דריסת method של ההורה speak() { return `${this.name} (${this.breed}) נובח: וף וף!`; } fetch() { return `${this.name} מביא מקל`; } } const rex = new Dog('רקס', 'לברדור'); rex.speak(); // "רקס (לברדור) נובח: וף וף!" rex.fetch(); // "רקס מביא מקל"

super — קריאה להורה

💻 הצג קוד דוגמה
class Vehicle { constructor(wheels) { this.wheels = wheels; } describe() { return `יש ${this.wheels} גלגלים`; } } class Car extends Vehicle { constructor(brand) { super(4); // קורא ל-constructor של Vehicle עם 4 this.brand = brand; } describe() { // משתמש ב-method של ההורה + מוסיף משלו return `${super.describe()} ל-${this.brand}`; } } const myCar = new Car('Toyota'); myCar.describe(); // "יש 4 גלגלים ל-Toyota"

Static methods

💻 הצג קוד דוגמה
class MathHelper { // static — שייך ל-Class עצמו, לא ל-instances static double(x) { return x * 2; } static add(a, b) { return a + b; } } // אין צורך ב-new MathHelper.double(5); // 10 MathHelper.add(2, 3); // 5

Private fields (חדש!)

💻 הצג קוד דוגמה
class User { #password; // # = פרטי, לא נגיש מבחוץ constructor(name, password) { this.name = name; this.#password = password; } checkPassword(input) { return this.#password === input; } } const u = new User('תל', 'secret123'); u.name; // 'תל' ✅ u.#password; // ❌ Error! u.checkPassword('secret123'); // true ✅

דוגמה ממבחן בנק

💻 הצג קוד דוגמה
class Customer { constructor(id, name, accounts = []) { this.id = id; this.name = name; this.accounts = accounts; } totalBalance() { return this.accounts.reduce((sum, acc) => sum + acc.balance, 0); } } class Account { constructor(id, type, balance = 0) { this.id = id; this.type = type; // 'checking' | 'savings' this.balance = balance; } deposit(amount) { if (amount <= 0) throw new Error('סכום לא תקין'); this.balance += amount; } withdraw(amount) { if (amount <= 0) throw new Error('סכום לא תקין'); if (amount > this.balance) throw new Error('יתרה לא מספקת'); this.balance -= amount; } } const acc1 = new Account(1, 'checking', 5000); const acc2 = new Account(2, 'savings', 10000); const customer = new Customer(101, 'תל', [acc1, acc2]); customer.totalBalance(); // 15000
שאלת מבחן קלאסית: "צור class בנק עם methods של deposit, withdraw, transfer". זכור: throw new Error לקלט לא תקין, validation לפני כל פעולה.

🟢 רמת סבתא

Class = תבנית ליצירת דברים. כמו תוכנית לבניית בית:

  • constructor = ההוראות — "הבית חייב להיות עם 3 חדרים ומרפסת"
  • methods = מה הבית יכול לעשות — "לפתוח דלת", "להדליק אור"
  • extends = ירושה — "וילה היא כמו בית רגיל, אבל עם בריכה"

🟡 רמת ביניים

💻 הצג קוד דוגמה
class BankAccount { #balance = 0; // private field constructor(owner, initialBalance) { this.owner = owner; this.#balance = initialBalance; } deposit(amount) { if (amount <= 0) throw new Error('Invalid amount'); this.#balance += amount; } withdraw(amount) { if (amount > this.#balance) throw new Error('Insufficient funds'); this.#balance -= amount; } get balance() { return this.#balance; } // getter } const acc = new BankAccount('תל', 1000); acc.deposit(500); // 1500 acc.withdraw(200); // 1300 acc.#balance; // ❌ SyntaxError (private!)

for...of vs for...in (חשוב!)

💻 הצג קוד דוגמה
const arr = ['a', 'b', 'c']; // for...of — נותן ערכים for (const value of arr) { console.log(value); // 'a', 'b', 'c' } // for...in — נותן מפתחות (אינדקסים במערך) for (const key in arr) { console.log(key); // '0', '1', '2' } const obj = { name: 'תל', age: 30 }; // for...in — מתאים לאובייקטים for (const key in obj) { console.log(key, obj[key]); // 'name תל', 'age 30' } // for...of — לא עובד ישירות על object for (const x of obj) { ... } // ❌ Error! // פתרון לאובייקט: for (const [key, value] of Object.entries(obj)) { console.log(key, value); }

break ו-continue

💻 הצג קוד דוגמה
// break — יוצא מהלולאה for (let i = 0; i < 10; i++) { if (i === 5) break; console.log(i); // 0, 1, 2, 3, 4 } // continue — מדלג על איטרציה for (let i = 0; i < 5; i++) { if (i === 2) continue; console.log(i); // 0, 1, 3, 4 (דילג על 2) }

forEach vs map vs filter

💻 הצג קוד דוגמה
const nums = [1, 2, 3]; // forEach — לא מחזיר כלום, רק עובר nums.forEach(n => console.log(n)); // undefined // map — מחזיר מערך חדש const doubled = nums.map(n => n * 2); // [2, 4, 6] // filter — מחזיר מערך מסונן const evens = nums.filter(n => n % 2 === 0); // [2]

slice vs splice (טעות נפוצה!) ⭐

זה אחד הבאגים הכי נפוצים! שתי הפונקציות נראות דומה אבל מתנהגות שונה לחלוטין.

🎂 slice vs splice = צילום עוגה לעומת חיתוך עוגה (משל סבתא)

סבתא אפתה עוגה. slice = מצלמת חתיכה (העוגה נשארת שלמה). splice = חותכת באמת (העוגה משתנה!).

📸 slice (אבטחה)
arr.slice(1, 3)
→ מחזיר העתק
→ המקור נשאר כפי שהוא
→ ב-React: תמיד מותר
🔪 splice (סכנה)
arr.splice(1, 2)
→ משנה את המערך עצמו
→ React לא יזהה שינוי!
→ ב-State: אסור!
slicesplice
משנה את המקור?❌ לא✅ כן!
מחזיר?מערך חדשהפריטים שהוסרו
שימושחיתוךהוספה/הסרה
💻 הצג קוד דוגמה
// slice(start, end) — חותך, לא משנה את המקור const arr = [1, 2, 3, 4, 5]; const sliced = arr.slice(1, 3); // [2, 3] console.log(arr); // [1, 2, 3, 4, 5] ← לא השתנה! // splice(start, deleteCount, ...items) — משנה את המקור const arr2 = [1, 2, 3, 4, 5]; const removed = arr2.splice(1, 2); // מסיר 2 פריטים מ-index 1 console.log(removed); // [2, 3] ← מה שהוסר console.log(arr2); // [1, 4, 5] ← המקור השתנה! // splice להוספה const arr3 = [1, 2, 5]; arr3.splice(2, 0, 3, 4); // ב-index 2, מסיר 0, מוסיף 3,4 console.log(arr3); // [1, 2, 3, 4, 5]

שימוש ב-React (חשוב!)

💻 הצג קוד דוגמה
// ❌ אסור — splice משנה את המקור! const handleRemove = (id) => { const index = items.findIndex(i => i.id === id); items.splice(index, 1); // mutate! setItems(items); // React לא יזהה }; // ✅ נכון — filter (יוצר מערך חדש) const handleRemove = (id) => { setItems(items.filter(i => i.id !== id)); }; // ✅ או slice const handleRemove = (index) => { setItems([...items.slice(0, index), ...items.slice(index + 1)]); };
שאלת מבחן: "מה ההבדל בין slice ל-splice?" — slice = חיתוך לא הורס. splice = פעולה ישירה על המקור.
🔍 הסבר מעמיק — לולאות + slice/splice

🟢 רמת סבתא

לולאה = סיבוב על רשימה. כמו לספור תלמידים בכיתה. for = עובר אחד אחד ברשימה. forEach = עושה משהו לכל אחד. map = עושה משהו ומחזיר רשימה חדשה.

slice = לחתוך חתיכה מעוגה (המקור לא נפגע). splice = לגזור חתיכה מהעוגה (המקור נפגע!).

🟡 רמת ביניים

💻 הצג קוד דוגמה
// שולחן מהיר — מתי מה? const nums = [1, 2, 3, 4, 5]; // forEach — לא מחזיר כלום nums.forEach(n => console.log(n)); // undefined // map — מחזיר מערך חדש const doubled = nums.map(n => n * 2); // [2,4,6,8,10] // filter — מסנן const evens = nums.filter(n => n % 2 === 0); // [2,4] // for...of = ערכים, for...in = מפתחות for (const val of [10, 20]) {} // 10, 20 for (const key in {a:1}) {} // 'a' // slice vs splice const arr = [1,2,3,4,5]; arr.slice(1,3); // [2,3] — המקור לא נפגע! arr.splice(1,2); // [2,3] — המקור הפך ל-[1,4,5]!

🔍 הסבר מעמיק — localStorage / sessionStorage

🟢 רמת סבתא

תחשבי על 3 סוגי אחסון:

  • localStorage = מחסן גדול במרתף. הכל נשאר עד שמוחקים.

6️⃣ Context API ⭐

תארי לך שאת מעבירה הודעה במשפחה. במקום שכל אחד יגיד לבא בתור (props drilling), את שמה הודעה על לוח המודעות שכולם רואים. Context זה לוח המודעות של React.

הבעיה: Props Drilling

💻 הצג קוד דוגמה
// ❌ בעייתי — props עוברים דרך הרבה שכבות function App() { const user = { name: 'תל' }; return <Layout user={user} />; } function Layout({ user }) { return <Sidebar user={user} />; // רק מעביר } function Sidebar({ user }) { return <Profile user={user} />; // רק מעביר } function Profile({ user }) { return <div>{user.name}</div>; // סוף סוף משתמש }

הפתרון: Context

💻 הצג קוד דוגמה
// 1. צור context import { createContext, useContext, useState } from 'react'; const UserContext = createContext(null); // 2. עטוף את האפליקציה ב-Provider function App() { const [user, setUser] = useState({ name: 'תל' }); return ( <UserContext.Provider value={{ user, setUser }}> <Layout /> </UserContext.Provider> ); } // 3. השתמש ב-context בכל מקום function Profile() { const { user, setUser } = useContext(UserContext); return <div>{user.name}</div>; // ישר! }

Context מלא עם Custom Hook

💻 הצג קוד דוגמה
// AuthContext.jsx import { createContext, useContext, useState } from 'react'; const AuthContext = createContext(null); export function AuthProvider({ children }) { const [user, setUser] = useState(null); const login = async (email, password) => { const res = await fetch('/api/login', { method: 'POST', body: JSON.stringify({ email, password }), headers: { 'Content-Type': 'application/json' } }); const data = await res.json(); setUser(data.user); }; const logout = () => { setUser(null); }; return ( <AuthContext.Provider value={{ user, login, logout }}> {children} </AuthContext.Provider> ); } // Custom Hook לשימוש נוח export function useAuth() { const context = useContext(AuthContext); if (!context) { throw new Error('useAuth must be used within AuthProvider'); } return context; } // שימוש function LoginForm() { const { login } = useAuth(); // ... } function Dashboard() { const { user, logout } = useAuth(); return ( <div> שלום {user.name} <button onClick={logout}>התנתק</button> </div> ); }

  • "מתי להשתמש ב-Context?" — מידע שצריך הרבה קומפוננטות (auth, theme)
