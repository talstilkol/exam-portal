🧩 התמונה הגדולה: סיכום ויזואלי

חיבור כל חלקי הפאזל (React $\rightarrow$ Network $\rightarrow$ Node $\rightarrow$ DB) למפות מוח שיעשו סדר.

🌐 ארכיטקטורת המערכת (Full-Stack Flow)

איך בקשה עוברת מקליק של משתמש ועד לשמירה במסד הנתונים וחזרה.

1. Client (React)

👤 משתמש לוחץ "התחבר".
🎣 onSubmit קורא לפונקציה אסינכרונית.
📦 הכנת הדאטה ל-JSON Object.
⌛ UI נכנס למצב Loading.

2. Network (HTTP)

🌍 שימוש ב-fetch או axios.
🛠️ שליחת POST /api/login.
🏷️ Headers:
Content-Type: application/json.
🛡️ (אופציונלי) צירוף JWT ב-Authorization.

3. Server (Node/Express)

🚪 app.post('/api/login') תופס את הבקשה.
👮 Middleware מאמת נתונים/טוקן.
🧠 Controller מריץ לוגיקה עסקית (הצפנה).
📞 פנייה אסינכרונית ל-DB.

4. Database (MongoDB)

📂 Mongoose מפעיל את ה-Model.findOne().
🔍 חיפוש מול BSON Tree (אינדקסים).
✅ החזרת מסמך (Document) לשרת.
⬅️ השרת עונה ל-React עם סטטוס (200/400).

💾 מפת מצבי זיכרון (Where is my State?)

הבלבול הכי גדול הוא איפה לשמור את המידע. הנה התשובה הסופית:

סוג State טכנולוגיה מיועדת טווח חיים (Lifespan) מתי להשתמש? דוגמה קלאסית
Local State useState / useReducer עד שהקומפוננטה עושה Unmount. מידע רלוונטי רק לאזור ספציפי במסך. טופס פתוח/סגור, חיפוש נוכחי, Modal.
Global State Context API / Redux עד ריענון הדף (Refresh). מידע שהרבה קומפוננטות צריכות "הרחק" אחת מהשנייה בלי Prop Drilling. הגדרות שפה, Theme (Dark Mode), סל קניות לפני תשלום.
Browser State localStorage / Cookies נשמר גם אחרי סגירת הדפדפן. דברים שחייבים להישאר גם מחר (אבל קשורים למכשיר של היוזר). JWT Token (ב-Cookie), העדפות UI, עגלה של אורח.
Server State MongoDB / SQL לנצח (או עד מחיקה אקטיבית). האמת המוחלטת (Source of Truth). נתונים עסקיים רגישים. רשימת הזמנות, פרטי משתמש בסיסיים, מלאי.

⏳ מפת האסינכרוניות (Async Jungle)

איך מנהלים זמנים בלי לתקוע את המערכת? השוואה ישירה.

שיטה מה זה נותן? יתרונות ✅ חסרונות ❌
Callbacks פונקציה שמועברת כפרמטר ומופעלת "כשיקרה משהו". עובד תמיד. מעולה ל-Events (כמו onClick) ולדברים חוזרים (setInterval). Callback Hell (פירמידת האבדון) כשיש תלות של בקשות זו בזו. קשה לתפוס שגיאות.
Promises אובייקט המייצג פעולה שתסתיים (או תיכשל) בעתיד (.then().catch()). שרשור שטוח. טיפול אחיד בשגיאות (catch אחד בסוף). אפשרות ל-Promise.all. תחביר מעט מסורבל. עדיין מצריך קוד פנימי בתוך then.
Async / Await "תחפושת" סינכרונית ל-Promises (Syntactic Sugar). מתנהג כאילו הוא מחכה לשורה לרדת. הקוד הכי קריא וברור. עובד עם try/catch טבעי של JS. שגיאה נפוצה: שכחת await תחזיר Promise ערום. חייב להיות בתוך פונקציית async.

⚛️ מעגל החיים ב-React (Lifecycle vs Hooks)

מתי בדיוק מופעל הקוד שלי? החיבור בין התיאוריה לפרקטיקה.

1. Mounting (לידה)

הקומפוננטה עולה למסך בפעם הראשונה.

useEffect(() => { ... }, [])
מעולה ל: קריאות שרת (Fetch), הגדרת טיימרים.
➔

2. Updating (חיים)

State או Props משתנים.

useEffect(() => { ... }, [state])
מעולה ל: חיפוש מחדש כשמשתנה משתנה.
➔

3. Unmounting (מוות)

הקומפוננטה יורדת מהמסך.

return () => { ... }
מעולה ל: ניקוי טיימרים (Memory Leaks).

🗄️ SQL מול NoSQL (במה לבחור?)

מאפיין SQL (MySQL, Postgres) NoSQL (MongoDB)
מבנה נתונים טבלאות חזקות, שורות ועמודות (Relational). אוספים (Collections) של מסמכי JSON (גמיש).
סכמה (Schema) קשיחה. חייבים להגדיר מראש כל עמודה. דינמית (Schemaless). אפשר לדחוף מה שרוצים (אם כי Mongoose מוסיף סכמה וירטואלית).
קשרים (Relations) מצוין. מתבסס על JOINs מורכבים בין טבלאות. פחות חזק. עדיף Embedding (לקנן נתונים) או Referencing (שמירת ID).
Scaling (גדילה) אנכית (Vertical) - שרת אחד חזק יותר. קשה לפצל. אופקית (Horizontal) - קל לפזר על פני הרבה שרתים פשוטים.
מתי לבחור בזה? מערכות פיננסיות, בנקים, דאטה שדורש דיוק אטומי (ACID). אפליקציות Web מהירות, נתונים גמישים שלא תמיד זהים (כמו פוסטים).

📁 ארכיטקטורת תיקיות (איפה אני שם את הקוד?)

💻 React (Frontend)

  • /components - חלקי UI קטנים (Button, Card, Input).
  • /pages - הדפים המלאים (Home, Dashboard). מורכבים מהרבה Components.
  • /context - קבצי המצב הגלובלי (AuthContext, ThemeContext).
  • /hooks - הוקים מותאמים אישית (useFetch, useAuth).
  • /services - פונקציות שמדברות עם השרת (`fetch` / `axios`). לא UI!

⚙️ Node.js (Backend)

  • server.js - נקודת הכניסה. הפעלת ה-`app.listen()`.
  • /routes - ה"כבישים". מגדיר אילו URL מפעילים אילו פונקציות (למשל `router.post('/login')`).
  • /controllers - ה"מוח". פה הלוגיקה מתבצעת (אימות, יצירת משתמש, חישובים).
  • /models - הגדרת הסכמות של מסד הנתונים (Mongoose Schemas).
  • /middlewares - ה"שומרים". בדיקת טוקן, איסוף שגיאות לפני הראוטר.
