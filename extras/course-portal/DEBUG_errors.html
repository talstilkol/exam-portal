⚛️ שגיאות Frontend (React + JS)

מה שרואים ב-Console של הדפדפן — DevTools (F12).

RUNTIME TypeError: Cannot read property 'X' of undefined ▶
😱 מה קרה?
ניסית לגשת ל-property של אובייקט שעדיין לא הוגדר. בדרך כלל קורה כשהקוד רץ לפני שה-fetch הסתיים, או שה-API החזיר null.
❌ הבעיה
const [user, setUser] = useState();
// user = undefined בהתחלה
return <div>{user.name}</div>; // 💥
✅ התיקון
// 1. Optional chaining
return <div>{user?.name}</div>;

// 2. Conditional render
if (!user) return <p>Loading...</p>;
return <div>{user.name}</div>;

// 3. Default state
useState({ name: '' });
→ useState → מלכודות JS
REACT Warning: Each child should have unique "key" prop ▶
😱 מה קרה?
React משתמש ב-key כדי לזהות אילו items השתנו. בלי key (או עם index!) הוא יבלבל ויעדכן את הפריט הלא נכון.
❌ הבעיה
{items.map(item => (
  <li>{item.name}</li>     // אין key
))}

{items.map((item, i) => (
  <li key={i}>{item.name}</li>  // ❌ index!
))}
✅ התיקון
{items.map(item => (
  <li key={item._id}>
    {item.name}
  </li>
))}
→ React Lists → כללי זהב
REACT setState לא גורם לרינדור (mutation) ▶
😱 מה קרה?
שינית state ישירות (push/splice) במקום ליצור עותק חדש. React משווה לפי reference — אותה כתובת = "לא השתנה" = אין רינדור.
❌ הבעיה
items.push(newItem);   // mutation!
setItems(items);          // אין רינדור 💥
✅ התיקון
// יצירת מערך חדש
setItems([...items, newItem]);

// או functional update (הכי בטוח)
setItems(prev => [...prev, newItem]);
→ Immutability → slice vs splice
REACT Maximum update depth exceeded (לולאה אינסופית) ▶
😱 מה קרה?
setState נקרא ב-render או ב-useEffect ללא dependencies → רינדור → setState → רינדור → ∞.
❌ הבעיה
useEffect(() => {
  setCount(count + 1);
});  // 💥 אין deps - רץ בכל רינדור
✅ התיקון
useEffect(() => {
  setCount(c => c + 1);
}, []);  // פעם אחת בלבד

// או: deps נכון
useEffect(() => {
  load(id);
}, [id]);  // רק כש-id משתנה
→ useEffect
JS SyntaxError: Unexpected token < in JSON at position 0 ▶
😱 מה קרה?
ניסית לעשות res.json() על תשובה שהיא לא JSON — לרוב HTML של 404 או דף שגיאה. ה-< הוא הסוגריים הראשונים של <!DOCTYPE>.
✅ התיקון
const res = await fetch(url);
if (!res.ok) {
  throw new Error(`HTTP ${res.status}`);
}
const data = await res.json();
לרוב הסיבה: URL שגוי (חסר /api), השרת לא רץ, או CORS.
→ fetch + Promises
REACT Invalid hook call. Hooks can only be called inside... ▶
😱 מה קרה?
קראת ל-Hook (useState/useEffect) במקום אסור: בתוך if, לולאה, פונקציה רגילה, או event handler.
❌ הבעיה
function Component() {
  if (loading) {
    const [x, setX] = useState(); // ❌
  }
  function handleClick() {
    useState();  // ❌
  }
}
✅ התיקון
function Component() {
  // ✅ תמיד ברמה העליונה
  const [x, setX] = useState();

  if (loading) return <Loading />;
  return <div>{x}</div>;
}
→ Hooks Rules

NODE Error: listen EADDRINUSE: address already in use :::3000 ▶
😱 מה קרה?
ה-port כבר תפוס — הפעלת את השרת פעמיים, או יש תהליך זומבי שלא נסגר.
✅ התיקון (Mac/Linux)

# הרוג אותו (החלף PID)

# או one-liner:

EXPRESS req.body is undefined ▶
😱 מה קרה?
לא הפעלת את ה-body parser. Express לא קורא בקשות JSON אוטומטית — צריך להגיד לו.
✅ התיקון
const app = express();

// ⚠️ חייב לפני ה-routes!
app.use(express.json());
app.use(express.urlencoded({
  extended: true
}));

app.use('/api', routes);
בנוסף — בצד הלקוח:
fetch(url, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(data)
});
→ Express Middleware → ראה ב-IDE: server.ts
NODE UnhandledPromiseRejectionWarning ▶
😱 מה קרה?
async function זרקה שגיאה ולא היה try/catch שיתפוס. ב-Node מודרני זה קורסים.
❌ הבעיה
app.get('/users', async (req, res) => {
  const users = await User.find();
  res.json(users);
});  // 💥 אם find() נכשל
✅ התיקון
app.get('/users', async (req, res) => {
  try {
    const users = await User.find();
    res.json(users);
  } catch (err) {
    res.status(500).json({
      error: err.message
    });
  }
});
→ try/catch

MONGOOSE CastError: Cast to ObjectId failed ▶

  });

🔐 שגיאות Authentication (JWT)

401, 403, ובעיות סיסמה.

AUTH 401 Unauthorized — JsonWebTokenError ▶
😱 מה קרה?
ה-token חסר/פגום/פג תוקף. או שה-JWT_SECRET שונה בין השרת ובין מי שחתם את ה-token.
✅ דברים לבדוק
// 1. הפורמט של ה-header:
headers: {
  Authorization: `Bearer ${token}`
}

// 2. בשרת — לאחזר נכון:
const token = req.headers.authorization
  ?.slice(7);  // בלי "Bearer "

// 3. אותו secret בכל מקום:
jwt.verify(token, process.env.JWT_SECRET!);

// 4. ה-token פג תוקף? בדוק ב-jwt.io
→ JWT Flow → middleware/auth.ts
AUTH Login נכשל למרות סיסמה נכונה ▶
😱 מה קרה?
בדרך כלל: שמרת סיסמה ב-DB בלי לעבור hash, או עשית hash פעמיים.
✅ התיקון — pre-save hook
userSchema.pre('save', async function(next) {
  // רק אם הסיסמה השתנתה
  if (!this.isModified('password')) {
    return next();
  }
  this.password = await
    bcrypt.hash(this.password, 10);
  next();
});

// ב-login:
const ok = await bcrypt.compare(
  plainPassword,
  user.password
);
→ bcrypt → models/User.ts

🌐 שגיאות CORS

למה הדפדפן חוסם בקשות בין דומיינים — וזה בכוונה!

CORS Access to fetch blocked by CORS policy ▶
😱 מה זה CORS?
Cross-Origin Resource Sharing — הגנה של דפדפנים. כשהפרונטנד (port 5173) קורא לבקאנד (port 3000) — זה "origins שונים". הדפדפן דורש מהשרת לאשר זאת מפורשות.
✅ התיקון בשרת (Express)
import cors from 'cors';

// פתוח לכולם (פיתוח):
app.use(cors());

// או ספציפי (production):
app.use(cors({
  origin: 'http://localhost:5173',
  credentials: true
}));

// לאחסון cookies — חובה credentials
⚡ טיפ זהב
CORS מטופל בשרת, לא בלקוח. אם אתה רואה את השגיאה — הבעיה בשרת.
→ Express + CORS → server.ts ב-IDE
CORS 405 Method Not Allowed (OPTIONS preflight) ▶
😱 מה קרה?
לפני בקשת PUT/DELETE/PATCH — הדפדפן שולח OPTIONS request כ"בדיקה". אם השרת לא תומך — הבקשה האמיתית לא נשלחת.
✅ התיקון
// cors() כבר מטפל ב-OPTIONS, אבל:
app.use(cors({
  methods: ['GET','POST','PUT','DELETE'],
  allowedHeaders: [
    'Content-Type',
    'Authorization'
  ]
}));
→ HTTP Methods
