🤿 צלילות עומק למבחן המעשי

ריכוז נושאים מתקדמים שחובה להכיר ברמת הפרויקט: Regex, ניהול תלויות והעלאה לפרודקשן.

🔍 Regex (ביטויים רגולריים)

ביטויים רגולריים (Regular Expressions) הם תבניות טקסט עוצמתיות לחיפוש, זיהוי והחלפה של מחרוזות. במבחן משתמשים בהם לרוב עבור ולידציות צד שרת (Mongoose) וצד לקוח (React).

סימנים בסיסיים

סימןמשמעותדוגמה למאצ'
^ ו- $תחילת וסוף מחרוזת (חובה לולידציה מדויקת)^hello$ (רק המילה hello)
[a-z]כל אות קטנה באנגלית[A-Z0-9] (אותיות גדולות ומספרים)
\dספרה (Digit) - זהה ל-[0-9]\d\d\d (3 ספרות ברצף)
\wאות, ספרה או קו תחתון (Word character)\w+ (מילה אחת לפחות)
.כל תו בעולם (חוץ משורת רווח).* (הכל)

כמתים (Quantifiers - כמות הפעמים)

סימןמשמעות
+פעם 1 או יותר (חובה שיופיע)
*0 פעמים או יותר (אופציונלי ויכול לחזור)
?0 או 1 פעמים (אופציונלי לחלוטין)
{n,m}בין n ל-m פעמים. למשל \d{2,4} (בין 2 ל-4 ספרות)

צ'יטשיט חובה למבחן (העתק-הדבק)

// 1. אימייל תקין (Mongoose & Frontend) const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/; // 2. סיסמה חזקה (לפחות 8 תווים, אות גדולה, אות קטנה, ומספר) const passwordRegex = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[a-zA-Z\d]{8,}$/; // 3. מספר טלפון ישראלי (05X-XXXXXXX או 05XXXXXXXX) const phoneRegex = /^05\d-?\d{7}$/; // 4. טקסט בעברית בלבד (עם רווחים) const hebrewRegex = /^[\u0590-\u05FF\s]+$/;

📦 קובץ ה-package.json

הלב הפועם של כל פרויקט Node/React. מנהל את הסקריפטים והתלויות (Dependencies) של הפרויקט. מבנה הקובץ קריטי לפרויקט שעובד כמו שצריך.

{ "name": "my-backend-app", "version": "1.0.0", "type": "module", // חובה! כדי להשתמש ב- import/export (במקום require) "scripts": { // הסקריפט ש-Vercel או חבר צוות יריץ כדי להתחיל "start": "node server.js", // סקריפט הפיתוח. משתמש ב-nodemon כדי שירת את השרת על כל שמירה "dev": "nodemon server.js", // במקרה של Frontend (Vite) יש גם: "build": "vite build" }, "dependencies": { // ספריות חובה שהאפליקציה צריכה כדי לרוץ (הולכות לשרת/לפרודקשן) "express": "^4.18.2", "mongoose": "^8.0.0", "cors": "^2.8.5", "dotenv": "^16.3.1" }, "devDependencies": { // ספריות שצריך *רק* לפיתוח (לא יעלו לפרודקשן) "nodemon": "^3.0.1" } }

פקודות npm קריטיות:

  • npm init -y - יצירת package.json בסיסי (השלב הראשון תמיד!)
  • npm i express mongoose cors dotenv - התקנת תלויות חובה ל-Backend
  • npm i -D nodemon - התקנת חבילה כ-devDependency (הדגל -D)
  • npm run dev - הרצת סקריפט ספציפי תחת "scripts"

🚀 צ'קליסט העלאה לפרודקשן (Deploy)

השלבים האחרונים כדי לוודא שהפרויקט שלכם מרונדר ללא שגיאות ב-Vercel / Render.

✓

1. הסתרת מפתחות סודיים (.env)

ודאו שאין סיסמאות Database או JWT Secrets כתובים בקוד השרת. תמיד השתמשו ב-process.env.MONGO_URI.

חשוב: בקובץ .gitignore חובה להוסיף .env כדי שלא יעלה ל-GitHub! בממשק של Vercel תצטרכו להגדיר את משתני הסביבה (Environment Variables) ידנית.
✓

2. כתובות (URLs) דינמיות ב-Frontend

אל תעשו fetch('http://localhost:3000/api/users')! בפרודקשן, ה-localhost לא קיים.

הפתרון: const API_URL = import.meta.env.PROD ? 'https://my-backend.vercel.app' : 'http://localhost:3000';
ואז להשתמש ב- fetch(`${API_URL}/api/users`).
✓

3. הגדרות ה-PORT ב-Backend

שרתי פרודקשן מספקים פורט משלהם, לכן השרת שלכם חייב להאזין לאותו הפורט.

const port = process.env.PORT || 3000;
app.listen(port, () => console.log('Server is running'));
✓

4. הגדרת CORS

ודאו שה-Backend מאפשר לקבל בקשות מה-Frontend שהרגע העליתם (שנמצא בדומיין אחר).

app.use(cors({ origin: ['https://my-frontend.vercel.app', 'http://localhost:5173'] }));
✓

5. טיפול בשגיאות SPA (בריאקט / Vite)

כשמעלים אפליקציית React / Vite ל-Vercel, ריענון דף יכול לגרום ל-404 בגלל ש-Vercel מחפש קובץ HTML באותו השם.

הפתרון: צרו קובץ בשם vercel.json בתיקייה הראשית של ה-Frontend שלכם: 
{
  "rewrites":  [
    {"source": "/(.*)", "destination": "/index.html"}
  ]
}
