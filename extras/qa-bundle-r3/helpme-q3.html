24ד. Function מול Arrow Function
25function רגילה מקבלת this משלה וניתנת ל־hoisting.

28ה. מה הפונקציה עושה?
29const func = (num) => {
30 if (num === 1) return 1;
31 return num * func(num - 1);
32}
33זו פונקציה רקורסיבית שמחשבת עצרת factorial.
34לדוגמה: func(5) = 5 * 4 * 3 * 2 * 1 = 120.

⚠️ כל האפשרויות לעשות טעויות — כדי שלא תטעי

  • לא לכתוב ש-GET יוצר נתונים
  • לא לכתוב של-Arrow יש this משלו
  • בפונקציה הרקורסיבית מדובר בעצרת ולא בפיבונאצ׳י

⚠️ טעויות מורחבות שלא ליפול בהן

  • לא לשנות מערך/אובייקט state ישירות. תמיד ליצור עותק עם spread או map/filter.
  • לא לשכוח value/onChange בכל input אם הוא controlled component.
  • checkbox צריך checked ולא value; select צריך value מתאים.
  • מספרים שמגיעים מ-input הם מחרוזות — להמיר עם Number לפני חישוב/בדיקה.
  • לא לנווט לפני שהוולידציות עברו; navigate רק בסוף פעולה תקינה.
  • ב-map חייבים key יציב לכל כרטיס/שורה.
  • לא להציג כפתורי ניווט למשתמש לא מחובר אם הדרישה אומרת לחסום.
  • לא לשכוח להחזיר JSX אחד עוטף בכל קומפוננטה.
  • לא לשכוח להתאים route/path בדיוק לדרישה: /add, /edit, /history וכו׳.
  • אם יש חיפוש חלקי — להשתמש ב-includes על lowercase כדי לא להיכשל בגלל אותיות גדולות/קטנות.
  • כשיש עריכה — לוודא שהטופס נטען מהאובייקט הנבחר ולא נשאר ריק.
  • בעיצוב: קודם פונקציונליות, אחר כך CSS; לא לאבד נקודות על לוגיקה בגלל עיצוב מוקדם.
