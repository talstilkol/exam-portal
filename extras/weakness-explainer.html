⚛️ React & Hooks — הסבר אסוציאטיבי

כל נקודות החולשה מוסברות ברמה שגם סבתא תבין, עם דוגמאות קוד ומשלים מהחיים

▼ ⚛️ React — ספריית UI מודרנית
הסבר לסבתא
דמיינו שאתם בונים בית מלגו. במקום לבנות קיר אחד ענק — אתם בונים חדרים נפרדים (רכיבים). כל חדר יודע מה יש בתוכו (state), ואפשר לשנות ריהוט בחדר אחד בלי להרוס את כל הבית.

React = בנייה מחדרים. כל חדר = Component. כל ריהוט = State. כל דלת בין חדרים = Props.
מושגמשלבקוד
Componentחדר בביתfunction LoginForm() { return <div>...</div> }
Propsדלת — מעבירים חפצים מחדר לחדר<Card title="שלום" />
Stateריהוט בחדר — משתנה רק בתוך החדרconst [name, setName] = useState("")
JSXתוכנית הבניין — איך החדר נראהreturn <h1>{name}</h1>
Re-renderשיפוץ — React מעדכן רק מה שהשתנהכשקוראים ל-setState
React = חדרים (Components) + ריהוט (State) + דלתות (Props). זה הכל!
▼ 🪝 Hooks — הכלים של React
הסבר לסבתא
Hooks זה כמו כלי עבודה בארגז כלים. כל כלי עושה משהו אחר:
🔨 useState = מגירה — שומרים ומוציאים דברים
🔌 useEffect = שעון מעורר — עושה משהו כשמגיעים או עוזבים
🔍 useRef = מדבקת סימון — מסמנים דבר מסוים בלי לזוז
🧮 useMemo = מחשבון עם זיכרון — לא מחשב שוב אם לא השתנה
📞 useCallback = מספר טלפון קבוע — אותה פונקציה, לא חדשה כל פעם

📦 useState — המגירה
הסבר לסבתא
יש לכם מגירה בשידה. אפשר לפתוח ולראות מה בפנים (לקרוא state), ואפשר להחליף את מה שבפנים (setState). כל פעם שמחליפים — React מסתכל מחדש ומעדכן את המסך. 
// מגירה של מספר (counter)
const [count, setCount] = useState(0);

// מגירה של טקסט (שם)
const [name, setName] = useState("");

// מגירה של אובייקט (טופס)
const [form, setForm] = useState({ name: "", email: "" });

// מגירה של מערך (רשימה)
const [items, setItems] = useState([]);
Patternמשלקוד
Boolean toggleמתג חשמל — דולק/כבויsetOpen(!open)
Functional updateקודם תבדוק מה במגירה, אז תוסיףsetCount(prev => prev + 1)
Resetרוקנו את המגירה והחזירו למקורsetForm({ name: "", email: "" })
Lazy initתפתח את המגירה רק כשצריךuseState(() => heavy())
אסור לגעת ישירות במגירה! items.push(x) = שבור. חייבים setItems([...items, x]) — להוציא הכל, להוסיף, ולשים מגירה חדשה.
⏰ useEffect — השעון מעורר
הסבר לסבתא
דמיינו שעון מעורר:
• [] ריק = מצלצל רק כשמגיעים לבית (mount) — פעם אחת
• [name] = מצלצל כל פעם שהשם משתנה
• return cleanup = כשעוזבים את הבית, מכבים את האור
בלי cleanup זה כמו לשכוח את הגז דלוק — memory leak! 
// רק בכניסה לבית (mount)
useEffect(() => {
  fetch('/api/data').then(r => r.json()).then(setData);
}, []);  // [] = רק פעם אחת

// כל פעם שהשם משתנה
useEffect(() => {
  document.title = `שלום ${name}`;
}, [name]);  // [name] = כשname משתנה

// עם ניקוי — כיבוי האור כשעוזבים
useEffect(() => {
  const id = setInterval(() => tick(), 1000);
  return () => clearInterval(id);  // 🧹 ניקוי!
}, []);
שכחתם cleanup ל-setInterval? הוא ימשיך לרוץ גם אחרי שהרכיב נעלם — memory leak! תמיד return () => clearInterval(id)
לולאה אינסופית: אם שמתם setState בתוך useEffect בלי deps — הוא ירוץ → ישנה state → ירוץ שוב → ישנה state → 💥
📌 useRef — המדבקה
הסבר לסבתא
useRef זה כמו מדבקת Post-it שמדביקים על משהו. אפשר לכתוב עליה ולשנות מה כתוב — אבל React לא שם לב (לא מרנדר מחדש). מושלם כשרוצים לסמן דבר בלי לגרום לשיפוץ. 
// מדבקה על input — כדי לעשות focus
const inputRef = useRef(null);
inputRef.current.focus();

// מדבקה עם ערך — לא גורם לרנדר מחדש
const renderCount = useRef(0);
renderCount.current += 1; // לא גורם לרנדר!
שימושמשללמה לא useState?
focus על inputלהצביע על שדהאין צורך ברנדר
ספירת רנדריםלספור בלי להפריעsetState יגרום ללולאה
ערך קודםלזכור מה היה קודםsetState ישנה את הנוכחי
DOM elementלתפוס אלמנטDOM ≠ state
🧮 useMemo & useCallback — חסכנות
הסבר לסבתא
useMemo = מחשבון עם זיכרון. אם חישבתם כבר את 5+3=8, ושואלים שוב 5+3 — הוא אומר "8" מיד בלי לחשב.
useCallback = מספר טלפון קבוע. במקום לתת לילד מספר חדש כל יום (שיגרום לו לעדכן את אנשי הקשר), נותנים לו את אותו מספר. 
// useMemo — לא מחשב שוב אם items לא השתנה
const sorted = useMemo(() => {
  return items.filter(i => i.active).sort((a,b) => a.name.localeCompare(b.name));
}, [items]);

// useCallback — אותה פונקציה, לא חדשה כל רנדר
const handleDelete = useCallback((id) => {
  setItems(prev => prev.filter(i => i.id !== id));
}, []);
אל תשתמשו ב-useMemo/useCallback על הכל! רק כשיש חישוב כבד או כשמעבירים פונקציה ל-child שעטוף ב-React.memo.

🛣 Routing — ניווט בין דפים

איך עוברים מדף לדף באפליקציית React — בלי לרענן את הדפדפן

▼ 🛣 React Router — מה זה?
הסבר לסבתא
דמיינו בניין עם דלת כניסה אחת (BrowserRouter) ושלטים שמכוונים לקומות (Routes). כשלוחצים על שלט "קומה 3" — לא יוצאים מהבניין ונכנסים מחדש. פשוט עולים בעליות (Link/Navigate). הכתובת בסרגל משתנה, אבל הדף לא נטען מחדש!
רכיבמשלמשמש לדוגמה
BrowserRouterדלת הכניסה לבנייןעוטף את כל האפליקציהאחד בלבד, ב-main.jsx
Routes + Routeשלטים לקומותהגדרת כתובת → רכיבpath="/login"
Linkכפתור מעליתניווט בלי reload<Link to="/home">
useNavigateמעלית אוטומטיתניווט מתוך קודאחרי submit מוצלח
useParamsמספר הדירהקריאת פרמטרים מ-URL/users/:id → id
useLocationGPS — איפה אני עכשיו?מידע על הכתובתpathname, state
// main.jsx — דלת הכניסה
<BrowserRouter>
  <App />
</BrowserRouter>

// App.jsx — השלטים לקומות
<Routes>
  <Route path="/" element={<Login />} />
  <Route path="/home" element={<Home />} />
  <Route path="/edit/:id" element={<Edit />} />
</Routes>

// ניווט עם Link — כפתור מעלית
<Link to="/home">עמוד הבית</Link>

// ניווט מקוד — מעלית אוטומטית
const navigate = useNavigate();
navigate("/home");  // אחרי login מוצלח

// קריאת מספר דירה מ-URL
const { id } = useParams();  // /edit/5 → id = "5"
useParams מחזיר תמיד string! אם צריך מספר: Number(id) או parseInt(id)
Link = למשתמש ללחוץ. useNavigate = הקוד מחליט לנווט (אחרי submit, אחרי login).

📝 Forms & Events — טפסים ואירועים

איך React מטפל בקלט מהמשתמש — כל לחיצה, כל הקלדה

▼ 📝 Controlled vs Uncontrolled
הסבר לסבתא
Controlled = כמו מזכירה שרושמת כל מילה שאתם אומרים. כל אות שמקלידים — היא כותבת במחברת (state), ואתם רואים מה כתוב (value).

Uncontrolled = כמו תיבת דואר. לא יודעים מה בפנים עד שפותחים (ref.current.value). לא עוקבים בזמן אמת.
גישהמשלמתיקוד
Controlledמזכירה — רושמת הכלולידציה real-time, טפסיםvalue={x} onChange={...}
Uncontrolledתיבת דואר — בודקים בסוףקבצים, performanceref={inputRef}
✅ Controlled inputs — המזכירה
// כל input חייב value + onChange
const [name, setName] = useState("");

<input
  type="text"
  value={name}              // מה רשום במחברת
  onChange={(e) => setName(e.target.value)}  // רושמים כל שינוי
/>
סוגprops נדרשיםמשל
input textvalue, onChangeשדה טקסט — כל אות נרשמת
input checkboxchecked, onChangeמתג — דולק/כבוי
input radiochecked, onChangeכפתורי רדיו במכונית
selectvalue, onChangeתפריט נפתח — בחירה אחת
textareavalue, onChangeמחברת — טקסט ארוך
🎯 Events — אירועים
הסבר לסבתא
אירוע = משהו שקרה. לחצו על כפתור? זה event. הקלידו אות? זה event. React מאפשר לכם לגיד "כשזה קורה — תעשה את זה".
Eventמתי קורהמשלשימוש
onClickלחיצהלחיצת פעמוןכפתורים, כרטיסים
onChangeשינוי ערךסיבוב כפתורinputs, select, checkbox
onSubmitשליחת טופסשליחת מכתבe.preventDefault()!
onKeyDownלחיצת מקשהקשת אצבעEnter לשליחה, Esc לביטול
onFocus/onBlurכניסה/יציאה משדההדלקת/כיבוי זרקורvalidation בעזיבת שדה
onMouseEnter/Leavehoverעכבר מרחף מעלtooltips, תפריטים
// onSubmit — שליחת טופס
const handleSubmit = (e) => {
  e.preventDefault();  // 🛑 עצור! אל תרענן דף!
  // עכשיו אפשר לטפל בנתונים
};

<form onSubmit={handleSubmit}>
  <input ... />
  <button type="submit">שלח</button>
</form>
תמיד e.preventDefault() ב-onSubmit! בלי זה הדפדפן ירענן את הדף וכל ה-state ייעלם.

🔄 State Management — ניהול נתונים

איפה לשמור state, איך להעביר בין רכיבים, ואיך לשרוד רענון דף

▼ 📊 איפה לשמור State?
הסבר לסבתא
יש 3 מגירות בגדלים שונים:
🗄 useState = מגירה אישית — רק החדר הזה רואה אותה. נעלמת כשסוגרים את החדר (unmount).
🏪 localStorage = כספת — שורדת גם כשמכבים את המחשב. צריך לפתוח ולסגור ידנית.
📢 Context = רמקול — כל הבית שומע. מושלם לדברים שכולם צריכים (מי מחובר? מצב כהה/בהיר?).
מקוםמשלחייםשימוש
useStateמגירה בחדרעד שהחדר נסגרשדות טופס, toggles
localStorageכספתעד שמוחקים ידניתusers, token, theme
Contextרמקולחיי האפליקציהauth, theme, language
💾 localStorage — הכספת
הסבר לסבתא
localStorage = כספת בקיר. שמים פנימה (setItem), מוציאים (getItem). הכספת שורדת גם כשהולכים ובאים (רענון דף). אבל — הכספת מקבלת רק טקסט! אם רוצים לשמור אובייקט — חייבים להפוך אותו לטקסט (stringify) ולהחזיר (parse). 
// שמירה לכספת — stringify כי הכספת מקבלת רק טקסט
localStorage.setItem("users", JSON.stringify(users));

// שליפה מהכספת — parse כדי להחזיר לאובייקט
const saved = JSON.parse(localStorage.getItem("users")) || [];

// ===== THE PATTERN — תמיד ככה =====
// 1. טעינה מהכספת כשנכנסים
const [users, setUsers] = useState(() => {
  const saved = localStorage.getItem("users");
  return saved ? JSON.parse(saved) : [];
});

// 2. שמירה לכספת כשמשתנה
useEffect(() => {
  localStorage.setItem("users", JSON.stringify(users));
}, [users]);
פעולהAPIטעות נפוצה
שמירהsetItem(key, JSON.stringify(val))שכחו stringify → [object Object]
שליפהJSON.parse(getItem(key))null אם לא קיים → צריך || ברירת מחדל
מחיקהremoveItem(key)שכחו ב-logout
stringify ← שמירה. parse ← שליפה. בלי זה הנתונים נשברים!
📢 Context — הרמקול
הסבר לסבתא
בלי Context: צריך לתת מכתב מיד ליד מחדר לחדר (props drilling — מעצבן!).
עם Context: שמים רמקול — כולם שומעים ישירות. מושלם ל: מי מחובר? מצב כהה? שפה? 
// 1. יוצרים רמקול
const AuthContext = createContext();

// 2. מחברים לחשמל (Provider)
<AuthContext.Provider value={{ user, login, logout }}>
  <App />
</AuthContext.Provider>

// 3. שומעים מכל מקום
const { user, logout } = useContext(AuthContext);

⚡ Lifecycle & Effects — שלבי חיים

מתי רכיב נולד, מתי הוא מתעדכן, ומתי הוא מת — ומה לעשות בכל שלב

▼ 🔄 שלבי חיים של רכיב React
הסבר לסבתא
לכל רכיב יש חיים — כמו אדם:
👶 Mount = לידה — הרכיב מופיע על המסך לראשונה. כאן מביאים נתונים מהשרת.
🔄 Update = גדילה — משהו השתנה (props או state). React מעדכן את המסך.
☠️ Unmount = פרידה — הרכיב נעלם מהמסך. חובה לנקות: לכבות טיימרים, לנתק listeners.
שלבמשלuseEffectמה לעשות
Mount 👶תינוק נולדuseEffect(() => {...}, [])fetch, listeners, timers
Update 🔄ילד גדלuseEffect(() => {...}, [dep])re-fetch, re-compute
Unmount ☠️עוזב את הביתreturn () => {...}cleanup! clear! close!
👶 Mount — הלידה
useEffect(() => {
  // נולדתי! בואו נביא נתונים
  fetch("/api/users")
    .then(r => r.json())
    .then(data => setUsers(data));
}, []);  // [] = רק בלידה, פעם אחת
🔄 Update — כשמשהו משתנה
// כל פעם ש-userId משתנה — מביאים נתונים חדשים
useEffect(() => {
  fetch(`/api/users/${userId}`)
    .then(r => r.json())
    .then(setUser);
}, [userId]);  // כשuserId משתנה → רץ שוב
שכחתם לשים dep ב-[] ? useEffect ירוץ על כל רנדר — יכול לגרום לאלפי fetch-ים!
☠️ Unmount — הפרידה (Cleanup)
הסבר לסבתא
כשעוזבים את הבית — מכבים אור, סוגרים ברז, מכבים גז. ב-React: מנקים interval, מסירים listener, סוגרים websocket. בלי זה — הם ממשיכים לרוץ ברקע ואוכלים זיכרון!
מה צריך ניקוימשלאיך מנקים
setIntervalשעון מתקתקclearInterval(id)
setTimeoutטיימר חד-פעמיclearTimeout(id)
addEventListenerמיקרופון פתוחremoveEventListener
WebSocketטלפון פתוחws.close()
AbortControllerביטול הזמנהcontroller.abort()
useEffect(() => {
  // הדלקנו שעון
  const id = setInterval(() => {
    setSeconds(s => s + 1);
  }, 1000);

  // כשעוזבים — מכבים את השעון!
  return () => {
    clearInterval(id);  // 🧹 ניקוי
  };
}, []);
אם שכחתם cleanup — useEffect ימשיך לרוץ גם אחרי שהרכיב נעלם. שעון שמתקתק ברקע = בזבוז זיכרון ובאגים!
🧠 Memoization — מתי לחסוך
הסבר לסבתא
דמיינו שכל פעם שמישהו שואל "כמה 573 × 841?" אתם מחשבים מחדש. useMemo = רושמים את התשובה על דף, ובפעם הבאה — קוראים ישירות. useCallback = נותנים לילד את אותו מספר טלפון (פונקציה) כל פעם, במקום חדש.
Hookמשלמתי כדאימתי מיותר
useMemoתשובה רשומה על דףfilter/sort על מערך גדולחישוב פשוט כמו 2+3
useCallbackמספר טלפון קבועprops לילד עם React.memoפונקציה שלא עוברת ל-child
React.memoילד שלא צריך לשמועchild שמקבל אותם propschild שמשתנה תדיר
כלל אצבע: אל תשתמשו ב-useMemo/useCallback עד שיש בעיית ביצועים. Premature optimization = שורש כל הרע!
