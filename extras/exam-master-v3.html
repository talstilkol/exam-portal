5️⃣ Reference vs Value בינוני

תארי לך פתק עם מספר טלפון. אם תיתני העתק של הפתק לחברה — היא תוכל לקרוע אותו ושלך יישאר. זה by value. אבל אם תיתני לה את הכתובת של הבית שלך, ושתיכן תיכנסו לאותו בית — אם היא תזיז ספה, גם את תראי. זה by reference.

Primitives by Value

let a = 10; let b = a; // b מקבל עותק b = 20; console.log(a); // 10 — לא השתנה

Objects by Reference

let obj1 = { name: 'תל' }; let obj2 = obj1; // אותו אובייקט! obj2.name = 'דן'; console.log(obj1.name); // 'דן' — השתנה גם! console.log(obj1 === obj2); // true

השוואת אובייקטים

{a: 1} === {a: 1} // false! ❌ (references שונים) [] === [] // false! const x = {a: 1}; const y = x; x === y; // true (אותו reference)

Shallow vs Deep Copy

Shallow מול Deep:

const original = { name: 'תל', address: { city: 'ת"א' } }; // Shallow ❌ const copy = { ...original }; copy.address.city = 'חיפה'; console.log(original.address.city); // 'חיפה' (!) // Deep ✅ const deepCopy = structuredClone(original); deepCopy.address.city = 'חיפה'; console.log(original.address.city); // 'ת"א'

איך זה משפיע על React?

// ❌ באג קלאסי — mutation const [user, setUser] = useState({ name: 'תל', age: 30 }); user.age = 31; // mutate! setUser(user); // React לא יזהה שינוי! // ✅ נכון setUser({ ...user, age: 31 });
למבחן: כל {}, [], ו-function inline ב-React גורמים ל-reference חדש בכל render. זו הסיבה ש-useMemo ו-useCallback קיימים.

6️⃣ השוואות — == / === / NaN בינוני

== vs ===

// == עושה type coercion (להימנע!) 1 == '1' // true ⚠️ 0 == false // true ⚠️ null == undefined // true ⚠️ // === בודק טיפוס + ערך (תמיד!) 1 === '1' // false ✅ 0 === false // false ✅

NaN — המספר המוזר

NaN מתנהג מוזר:

NaN === NaN // false! Number.isNaN(NaN) // true ✅ (הדרך הנכונה) isNaN('abc') // true ⚠️ (גם strings!) Number.isNaN('abc') // false ✅ (רק NaN ממש)

typeof — מלכודות

typeof null // 'object' ⚠️ באג היסטורי typeof [] // 'object' ⚠️ לא 'array' typeof NaN // 'number' ⚠️ typeof function(){} // 'function' // הדרך הנכונה לבדוק: Array.isArray([]) // true ✅ value === null // true רק ל-null Number.isNaN(value) // true רק ל-NaN ממש
למבחן: תמיד ===. ל-NaN — Number.isNaN(). למערך — Array.isArray().

8️⃣ Async ו-Event Loop קשה

JS עובד בתור אחד — קופאית בסופר. היא יכולה לטפל רק בלקוח אחד בכל פעם. אבל יש לה רשימה: קודם דברים דחופים (microtasks), ואז דברים פחות דחופים (macrotasks).

סדר ההרצה

console.log('1'); // sync setTimeout(() => console.log('2'), 0); // macrotask Promise.resolve().then(() => console.log('3')); // microtask console.log('4'); // sync // סדר: 1, 4, 3, 2 // 1. sync code: 1, 4 // 2. microtasks: 3 // 3. macrotasks: 2

Promise

Promise זה אובייקט שמייצג ערך עתידי:

const promise = new Promise((resolve, reject) => { setTimeout(() => resolve('הצלחה!'), 1000); }); promise .then(result => console.log(result)) .catch(error => console.error(error)) .finally(() => console.log('סיים'));

async / await

async function getUser() { try { const res = await fetch('/api/user'); const data = await res.json(); return data; } catch (err) { console.error(err); } }

הרצה מקבילית

// ❌ טורי — איטי (3 שניות) const a = await fetchA(); const b = await fetchB(); // ✅ מקבילי — מהיר (1 שנייה) const [a, b] = await Promise.all([fetchA(), fetchB()]); // אם אחד נכשל = הכל נכשל // Promise.allSettled — לא נכשל const results = await Promise.allSettled([fetchA(), fetchB()]);

Promise Combinators

מתודהמתי מסתיימת
Promise.allכשכולן הצליחו / ראשון נכשל
Promise.allSettledכשכולן הסתיימו (גם אם נכשלו)
Promise.raceהראשון להסתיים
Promise.anyהראשון שהצליח

Race condition ב-React

// ❌ בעיה useEffect(() => { fetch(`/api/users/${userId}`).then(setUser); }, [userId]); // ✅ פתרון: cleanup useEffect(() => { let cancelled = false; fetch(`/api/users/${userId}`) .then(r => r.json()) .then(d => { if (!cancelled) setUser(d); }); return () => { cancelled = true; }; }, [userId]); // ✅ מתקדם: AbortController useEffect(() => { const controller = new AbortController(); fetch(url, { signal: controller.signal }); return () => controller.abort(); }, [url]);

9️⃣ Closures + הבאגים ב-React קשה מאוד

תארי לך פתק עם הוראה. כשאת רושמת — את "צילמת" את כל מה שהיה במטבח באותו רגע. גם אם אחר כך תשני את המטבח — הפתק יזכור את המצב הישן.

Closure = פונקציה שזוכרת את הסביבה שלה.

דוגמה בסיסית

function createCounter() { let count = 0; // משתנה פנימי return function() { count++; // הפונקציה זוכרת את count! return count; }; } const counter = createCounter(); counter(); // 1 counter(); // 2

באג #1: setTimeout עם state ישן

function Counter() { const [count, setCount] = useState(0); const handleClick = () => { setTimeout(() => { setCount(count + 1); // ⚠️ ה-closure תופס count ישן! }, 3000); }; } // ✅ פתרון: functional update const handleClick = () => { setTimeout(() => { setCount(prev => prev + 1); // תמיד עדכני }, 3000); };

באג #2: setInterval עם deps חסרות

// ❌ באג useEffect(() => { const id = setInterval(() => { setSeconds(seconds + 1); // תמיד 0! }, 1000); return () => clearInterval(id); }, []); // ⚠️ deps ריק // ✅ פתרון: functional update useEffect(() => { const id = setInterval(() => { setSeconds(prev => prev + 1); }, 1000); return () => clearInterval(id); }, []);

באג #3: לולאה עם var

// ❌ var (function-scoped) for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); } // תוצאה: 3, 3, 3 ⚠️ // ✅ let (block-scoped) for (let i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); } // תוצאה: 0, 1, 2 ✅

חוקי סבתא ל-Closures

  1. פונקציה שמוחזרת/מועברת — זוכרת את הסביבה שלה
  2. ב-React: כל render יוצר closures חדשים. הישנים לא מתעדכנים
  3. state בתוך setTimeout/Promise → functional update
  4. useEffect משתמש במשתנה → תוסיף ל-deps
  5. תמיד let/const

Custom Hook

function useFetch<T>(url: string) { const [data, setData] = useState<T | null>(null); const [loading, setLoading] = useState(true); const [error, setError] = useState<Error | null>(null); useEffect(() => { let cancelled = false; fetch(url) .then(r => r.json()) .then(d => { if (!cancelled) { setData(d); setLoading(false); }}) .catch(e => { if (!cancelled) { setError(e); setLoading(false); }}); return () => { cancelled = true; }; }, [url]); return { data, loading, error }; }

useReducer

type State = { count: number }; type Action = { type: 'inc' } | { type: 'dec' }; function reducer(state: State, action: Action): State { switch (action.type) { case 'inc': return { count: state.count + 1 }; case 'dec': return { count: state.count - 1 }; } } const [state, dispatch] = useReducer(reducer, { count: 0 }); dispatch({ type: 'inc' });

זרימת Login עם JWT

  1. משתמש שולח email + password
  2. שרת בודק מול DB
  3. אם תקין → יוצר JWT עם userId
  4. שולח חזרה את ה-token
  5. הקליינט שומר (localStorage / cookie)
  6. בכל בקשה — שולח Authorization: Bearer <token>
  7. שרת בודק את החתימה ומחלץ userId

Hashing סיסמאות

Hashing סיסמאות:

const bcrypt = require('bcrypt'); // שמירה const hash = await bcrypt.hash(password, 10); await User.create({ email, password: hash }); // בדיקה const user = await User.findOne({ email }); const valid = await bcrypt.compare(password, user.password); // ❌ לא לשמור סיסמאות בפלאש! // ❌ לא לשמור hash הפיך כמו MD5/SHA1!

חוקי אבטחה בסיסיים

  • HTTPS תמיד
  • סיסמאות עם bcrypt (לא MD5/SHA)
  • Rate limiting (להגן מ-brute force)
  • CORS מוגדר נכון
  • SQL Injection — פתרון: parameterized queries / ORM
  • XSS — escape user input
  • CSRF — tokens
  • אסור לשמור סיסמאות / API keys בקוד
